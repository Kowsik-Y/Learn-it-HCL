Solution Documentation

Learn-it HCL

AI-Powered Personalized Learning Path Recommender

01 Executive Summary

Learn-it HCL is an evidence-based, AI-powered learning platform that delivers personalized learning experiences tailored to each individual's knowledge state, interests, learning patterns, and career goals.

Unlike traditional platforms that equate video completion with competence, Learn-it HCL quantifies true mastery using probabilistic Bayesian models, predicts memory retention through spaced repetition scheduling, detects dropout risk before it happens, and explains every recommendation it makes.

Core Mission: Understand the learner → Quantify true mastery → Predict memory retention & dropout risk → Deliver adaptive personalized learning → Explain every decision.

02 Problem Statement

Online learning platforms offer thousands of courses across diverse domains. While basic recommendation systems can suggest relevant courses, learners face critical challenges:

  • Sequencing Gap — Difficulty identifying the right sequence of resources to achieve a specific goal
  • One-Size-Fits-All — Different learners have different skill levels, interests, and career aspirations
  • False Mastery — Traditional platforms treat watching a video as competence, without measuring true understanding
  • Retention Decay — Without spaced repetition, learners forget up to 80% of material within a week
  • Silent Dropout — Platforms lack early warning systems for learner disengagement
  • Black-Box Recommendations — Learners don't understand why certain resources are recommended

03 Solution Overview

Learn-it HCL addresses these gaps through six integrated components:

3.1 Conversational AI Onboarding

An LLM-powered conversational interface where learners describe their goals in natural language. The system diagnoses background knowledge, career aspirations, and preferred learning style through a multi-turn dialogue.

3.2 Learner Profiling Engine

Captures and continuously updates a rich learner profile encompassing interests, experience level, completed courses, skill mastery states (via BKT), memory retention curves (via FSRS), and learning objectives.

3.3 AI Recommendation Engine

An 11-stage recommendation pipeline that interprets goals, identifies prerequisite skill gaps, filters and ranks resources, and generates a personalized learning path with courses, projects, and assessments.

3.4 Personalized Learning Path Generator

Produces structured roadmaps with prerequisite ordering as a Directed Acyclic Graph (DAG), duration estimates, and milestone markers. Paths adapt dynamically based on learner progress and feedback.

3.5 Explainable AI Assistant

Every recommendation, video selection, quiz question, and risk flag comes with a human-readable "Why this?" explanation. The AI tutor assistant answers follow-up queries and provides contextual guidance.

3.6 Progress Dashboard

A unified dashboard visualizing skill development through mastery rings, XP progression, daily missions, active quests, spaced review queues, streak tracking, and next recommended actions.

07 ML Models — Technical Deep Dive

7.1 Bayesian Knowledge Tracing (BKT)

BKT is a probabilistic Hidden Markov Model (HMM) that tracks the latent mastery state of a learner for each skill. Unlike simple quiz scores, BKT maintains a probability distribution over whether a learner truly "knows" a skill.

Parameters

ParameterSymbolDefaultDescription
Initial PriorP(L0)0.10Probability the learner already knows the skill before any observation
Learning RateP(T)0.15Probability of transitioning from "not mastered" to "mastered" after an attempt
Slip RateP(S)0.10Probability of an incorrect response despite knowing the skill
Guess RateP(G)0.20Probability of a correct response despite not knowing the skill

Update Algorithm

For each learner attempt (correct or incorrect), a two-step Bayesian update is performed:

  1. Posterior Calculation — Given the observation, compute the posterior probability of mastery:
    If correct: P(Lt | correct) = P(L) × (1 − P(S)) / [P(L) × (1 − P(S)) + (1 − P(L)) × P(G)]
    If incorrect: P(Lt | incorrect) = P(L) × P(S) / [P(L) × P(S) + (1 − P(L)) × (1 − P(G))]
  2. Learning Transition — Account for the learner potentially learning from the attempt:
    P(Lt+1) = P(Lt | obs) + (1 − P(Lt | obs)) × P(T)

The model also outputs a confidence score (how certain the estimate is) and information gain (KL-divergence from previous estimate). Item difficulty weighting adjusts slip, guess, and transition parameters per-question.

7.2 Free Spaced Repetition Scheduler (FSRS v4)

FSRS v4 is a machine-learning spaced repetition algorithm that outperforms SM-2 and Leitner systems. It models two hidden variables per skill card: Difficulty (D) [1–10 scale] and Stability (S) [in days], then calculates Retrievability (R) — the probability of recalling the material at any point in time.

Memory Decay Formula

R(t, S) = (1 + t / (9 × S))−1
Where t = elapsed days since last review, S = memory stability in days.

Optimal Review Interval

The next review is scheduled at the precise moment retrievability drops to the desired retention target (default 90%):

Interval = 9 × S × (Rdesired−1 − 1)

Rating System

RatingMeaningEffect on Stability
1 — AgainForgottenStability drops sharply (lapse formula)
2 — HardRecalled with major effortStability increases slightly (hard penalty applied)
3 — GoodRecalled successfullyStability increases normally
4 — EasyRecalled effortlesslyStability increases substantially (easy bonus applied)

The model uses 17 trained weights controlling initial stabilities, difficulty dynamics, recall/forget stability curves, and hard/easy bonus multipliers. Stability is clamped between 0.1 and 3,650 days (10 years).

7.3 2-Parameter Logistic IRT + Computerized Adaptive Testing

Item Response Theory (IRT) models the interaction between learner ability (θ) and question characteristics. The platform uses the 2-Parameter Logistic (2PL) model.

2PL Probability Function

P(correct | θ, a, b) = 1 / (1 + e−a(θ − b))
Where a = discrimination [0.2–3.0], b = difficulty [−3.0 to +3.0], θ = learner ability [−4.0 to +4.0]

Fisher Information

Each question provides a measurable amount of diagnostic information about the learner's ability:

I(θ) = a² × P(θ) × (1 − P(θ))
Questions where the learner has a ~50% chance of answering correctly provide the most information.

Ability Estimation

Learner ability θ is estimated via Newton-Raphson Maximum Likelihood Estimation (MLE) — an iterative optimization that converges on the most likely ability given the response pattern. Standard error SE(θ) = 1 / √(ΣI(θ)) quantifies estimation precision.

Adaptive Question Selection (CAT)

The CAT engine selects the next question that maximizes Fisher Information at the learner's current estimated θ. Stopping criteria:

  • Precision achieved — SE(θ) drops below target (default 0.35)
  • Min/max bounds — Between 3 and 10 questions administered
  • Pool exhausted — No more unasked questions available

This reduces required question count by ~60% compared to fixed-length assessments while maintaining diagnostic accuracy.

A logistic regression model that scores learner churn probability (0–100%) from behavioral telemetry signals. Trained via SGD on historical student outcome data (churned vs. active).

7.5 Neural Video Ranker

A PyTorch 3-layer MLP that re-ranks curated YouTube video tutorials for each lesson by matching learner ability level with video characteristics. Automatically uses CUDA GPU if available.

7.6 Eleven-Stage Recommendation Pipeline

The recommendation engine uses a deterministic, weighted scoring pipeline — not LLMs for ranking decisions. LLMs are used only for explanation generation.

09 Data Model

The platform uses a PostgreSQL database with Prisma (frontend) and SQLAlchemy Async (backend) as dual ORMs. Key entity groups:

User & Identity

  • User — Profile, credentials, preferences, and role assignments
  • Tenant / Organization — Multi-tenant isolation with row-level security
  • Session — JWT-based authentication state

Learning Content

  • Course → Module → Lesson — Hierarchical curriculum structure
  • Video — Curated YouTube resources linked to lessons with difficulty metadata
  • Quiz / Question — Assessment items with IRT parameters (discrimination, difficulty)

Learner State

  • BKT State — Per-skill mastery probability P(Lt), prior, transition, slip, and guess parameters
  • FSRS Card — Stability, difficulty, interval, and next review date per skill
  • IRT Ability — Estimated learner ability θ from adaptive testing
  • Progress Tracking — Course enrollment, lesson completion, XP, streaks, and achievements

Analytics

  • Dropout Risk Score — Computed attrition probability with feature breakdown
  • Recommendation Log — Audit trail of recommendations with explainability strings

11.3 Automated Quick Setup (Recommended)

The project includes initialization scripts that set up both Node.js and Python environments, install all dependencies, generate Prisma client, create the super admin account, and produce .env files automatically.

One Command Setup: The init script handles everything — dependency installation, virtual environment creation, Prisma generation, database schema push, and super admin account creation.
PlatformCommand
macOS / Linuxchmod +x init.sh && ./init.sh
Windows (PowerShell).\init.ps1

The init script performs the following steps automatically:

  1. Enables pnpm via Corepack and runs pnpm install for the Next.js frontend
  2. Copies .env.example → .env for both web and backend
  3. Generates the Prisma client (npx prisma generate)
  4. Temporarily starts the database container to push the schema and create the Super Admin account
  5. Creates a Python virtual environment and installs all ML dependencies (pip install -e ".[dev]")

11.4 Manual Setup (Step-by-Step)

Step 1 — Install Frontend Dependencies

# From project root corepack enable pnpm pnpm install # Setup frontend environment cd apps/web cp .env.example .env npx prisma generate cd ../..

Step 2 — Install Backend Dependencies

# From project root cd backend # Create Python virtual environment python3 -m venv venv # Activate virtual environment source venv/bin/activate # macOS/Linux # .\venv\Scripts\activate # Windows # Install all dependencies (including dev tools) pip install -e ".[dev]" # Create backend .env (if not exists) cp .env.example .env # Or use the defaults deactivate cd ..

Step 3 — Start the Database

# Start PostgreSQL via Docker (port 5433 → internal 5432) docker-compose up -d db # Verify it's running docker-compose ps

Step 4 — Initialize Database Schema & Seed Data

# Push Prisma schema to database cd apps/web npx prisma db push # Seed the database with the Super Admin, organizations, and roles npx prisma db seed # Return to root cd ../.. # Seed ML-related data (learners, courses, BKT/FSRS states, quiz items) cd backend source venv/bin/activate python -m scripts.seed deactivate cd ..
Two-Phase Seeding: The Prisma seed creates the foundational schema (organizations, roles, super admin). The backend seed populates all ML-related data — learners, courses, skill trees, BKT mastery states, FSRS cards, IRT question banks, and demo progress.

15 Security & Multi-Tenancy

  • Authentication — JWT-based session management via Next.js API gateway with bcrypt password hashing

  • Multi-Tenancy — Row-level tenant_id isolation enforced at gateway and database level
  • Gateway Auth — ML microservice validates X-User-Id and X-Tenant-Id headers from the gateway
  • Secrets Management — Environment-based configuration with .env files excluded from version control
  • Token Lifecycle — Configurable access token expiry (default 30 min) and refresh tokens (default 7 days)
